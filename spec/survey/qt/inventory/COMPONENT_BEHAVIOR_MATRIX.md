# Component–behavior applicability matrix

Status: step 10 proposal complete. All 94 original entries are evaluated against the 40 response concepts, giving 3,760 classified cells. This is specification research, not executable capability detection.

## Codes and interpretation

- **I — intrinsic capability:** supplied as part of the component's documented role; still depends on valid state and user/application input. It does not mean mandatory execution or bypass disabled/read-only state.
- **O — optional/configured:** present when the documented configuration, target and platform allow it.
- **A — application/composition supplied:** wiring, policy, owned child or external action supplies the response. The named object alone is insufficient.
- **U — unresolved support:** the desired generic contract is not established for the target by the evidence; validate the adapter/capability before use.
- **N — not assigned:** every ID absent from I/O/A/U in a row. This is an explicit negative mapping at the surveyed concept boundary, not a claim that inheritance or arbitrary application code can never add it.

The four lists are mutually exclusive. N completes each row to all 40 concepts. This compact form avoids a 40-column table; the [machine-readable companion](COMPONENT_BEHAVIOR_MATRIX.json) enumerates every cell and uses the same codes. Configuration-specific limits in the [audit](BEHAVIOR_INVENTORY.md) and the [contracts](BEHAVIOR_CONTRACTS.md) take precedence over a bare I/O label.
