# Behavior proposal decisions

These decisions complete the proposal; canonical acceptance and target-adapter implementation are later merge activities. They are proposed explicit decisions, not claims that framework documentation prescribes these exact names or representations.

| ID | Proposed decision | Evidence / implication |
|---|---|---|
| D01 | Keep ownership in components. Behavior targets are ID references stored under attrs, resolving within the UI document; they neither own nor duplicate targets. Reject missing, wrong-kind and cyclic attachment references. | Existing scope serialization and separation of composition from interaction; [scope rules](../../../scopes/scope.md). Values remain prose contracts until converter/schema support is chosen; no schema change is claimed. |
| D02 | Combine modal restriction and modal focus into P05. A boundary references the root of the interaction region containing the modal target. On activation save eligible focus, restrict outside-target interaction within that boundary and enter the target. Deactivate in reverse nesting order; restore a valid invoker or workflow fallback. | [Qt dialog](https://doc.qt.io/qt-6/qdialog.html), [web modal pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/). Native window/application scope is an adapter mapping, not a universal web runtime. Unsupported enforcement is rejected rather than downgraded silently. |
| D03 | Combine base motion, optional kinetic motion and reveal-target into P06. Position uses normalized fractions on each available axis, clamped to 0–1; zero content range resolves to zero. The adapter converts to platform coordinates. Bar policies stay on the container. Stop prior motion before applying a conflicting new request. | [Scroll area](https://doc.qt.io/qt-6/qscrollarea.html), [Scroller](https://doc.qt.io/qt-6/qscroller.html). Normalized units and conflict arbitration are proposed neutral choices, not Qt API signatures. |
| D04 | Reuse the previous four leaves and add only P05/P06. Keep exclusivity in Choice controls, region selection in Graphics viewport and current-content switching in Page stack/Tabs. Their definitions remain reusable references, without independent leaves in this proposal. | [Behavior hierarchy](BEHAVIOR_TAXONOMY_PROPOSAL.md). Three existing behavior leaves remain the destinations for collapse, resize and drag/drop. |
| D05 | Text completion references an input by ID; candidates are ordered strings. Acceptance replaces the currently offered completion range, emits acceptance and does not submit. The host adapter must define that range before showing a suggestion. Dismissal preserves typed content. | [Completion](https://doc.qt.io/qt-6/qcompleter.html). Popup/inline modes have different accessibility patterns. No async service or result-object schema is introduced. |
| D06 | Graphics viewport borrows scene data through an opaque application resource reference. Resolution is adapter supplied; absence is an explicit unsupported-resource result. It owns no duplicate scene tree. Shared scenes and transforms retain one owner. | [Graphics view](https://doc.qt.io/qt-6/qgraphicsview.html), [scene](https://doc.qt.io/qt-6/qgraphicsscene.html). The proposal does not prescribe a rendering engine or promise generator support for that resource. |
| D07 | Swipes, hover, key/pointer input and timers are trigger/condition vocabulary. Map them to explicit outcomes; keep pointer hover different from focus. A target must provide alternatives appropriate to its chosen pattern. | [Gesture guide](https://doc.qt.io/qt-6/gestures-overview.html), [hover/focus content guidance](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html). Visual highlighting alone remains appearance; reveal-on-hover and swipe dismissal are application policies unless evidence establishes them. |
| D08 | Live preview is application-supplied. Cancellation reports intent; rollback occurs only under a declared recoverable baseline. Operation cancellation likewise waits for application confirmation. | [Color dialog](https://doc.qt.io/qt-6/qcolordialog.html), [progress dialog](https://doc.qt.io/qt-6/qprogressdialog.html). No universal transactional guarantee is inferred. |
| D09 | Use one controlling policy for each target/capability. Component convenience settings must agree with attached behavior settings; reject conflicting authority. Respect active modality before starting background scroll/drag. Declare priority between pan, spatial selection, item drag and text selection. | Proposed composition rule informed by [gesture handling](https://doc.qt.io/qt-6/gestures-overview.html) and [view interaction](https://doc.qt.io/qt-6/qgraphicsview.html). Full event-dispatch implementation belongs to adapters. |

## Remaining acceptance and implementation boundaries

- Host-shell presence remains deferred; notification delivery and native floating windows need capability checks.
- All six leaves are review drafts. Canonical evidence approval, generator support and platform accessibility conformance are not established by this document.
- Temporal-value serialization and rich-document payloads are existing-family enrichment questions; the behavior contracts use domain values without prescribing a new payload format.
- These boundaries are recorded proposal outcomes, not unperformed steps 10–14.
