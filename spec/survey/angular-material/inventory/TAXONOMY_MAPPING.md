# Angular Material to canonical taxonomy crosswalk

Status: proposed mapping for a future merge, based on the current [canonical mapping](../../../scopes/taxonomy_mapping.md), [scope rules](../../../scopes/scope.md), [leaf template](../../../scopes/template.scope.md), and [evidence register](../../../scopes/evidence.md). Those documents define the specification conventions; they are not a request to change the canonical tree. The user's request authorizes this review package.

The survey categories organize research; canonical scopes organize UI semantics. Reuse the existing 11 roots. The five proposed new leaves and thirteen existing-leaf enhancements are detailed in the [extension proposal](SCOPE_EXTENSION_PROPOSAL.md); the [behavior crosswalk](BEHAVIOR_MAPPING.md) adds capability relationships to this object-family mapping. All proposals remain unapproved.

## Mapping rules

The four abstraction-level names retain their meanings from the canonical mapping. “Proposed” marks a candidate addition, and “Not applicable” marks implementation-only evidence outside those four levels. Reuse, enhancement and addition are merge dispositions, not new abstraction levels. Multiple targets mean contextual composition or distinct facets, not duplicate ownership of one source object.

Coverage is at category and family level, with artifact-role rules for every inventoried file, folder and export. Counts are inventory objects, not counts of UI concepts or public symbols. This is not a per-symbol API mapping. Source evidence remains pinned to Angular Material 22.1.7 at commit `e950f29dcfbda93c13bff0d1a632465364488249`; see [baseline](BASELINE.md).

## Worked ambiguous cases

- A `form-field` theme file remains Presentation evidence for AM-P01; it does not define another field type.
- A static chip may map to Tag, a selection-only chip to Choice controls, and an editable coordinated collection to AM-P02. A chip's rounded shape does not decide the mapping.
- Sidenav is structurally a sheet. Its route links may additionally instantiate application navigation; the container itself need not navigate.
- A tree remains mapped to the existing navigation family while its description is broadened to hierarchical data. Moving it would require a separately reviewed migration.
- Core date adapters support internationalization; Angular dependency-injection tokens and provider classes stay implementation evidence.

The [candidate evidence register](PROPOSED_EVIDENCE.md) records what each proposed change would authorize after acceptance. No framework API name becomes a canonical type automatically.

## Secondary behavior mapping

The [behavior crosswalk](BEHAVIOR_MAPPING.md) adds a second dimension without changing primary object ownership: all 40 observations and all 39 families have dispositions. The family table above identifies what an object is; the new crosswalk identifies which capabilities apply, with evidence and configuration qualifiers.

- Dialog and explicitly modal sheets can compose AM-P03 Modal interaction while retaining host lifecycle and semantics.
- Dialog content, drawer content and applicable tab bodies can compose AM-P04 Scrollable. A scrollbar control or the pending Qt Scroll container remains a separate concept.
- AM-P05 Scroll lock targets the background page; it does not disable internal surface scrolling or establish modality.
- Expansion and tree disclosure support AM-E10's broader Collapsible applicability; AM-E13 keeps panel state/actions on one owner.
- Ordering/filtering/paging reuse existing Table/List Behaves contracts where applicable. Reusable scopes, Uses configuration, Produces notifications and cross-cutting mechanisms remain distinct.

The [structural decisions](BEHAVIOR_MAPPING.md#structural-decisions) assess possible new categories and subcategories. No new canonical folder/root is recommended at present; three new leaves fit the existing Behaviors parent. Deferred candidates and migration implications remain explicit in the review.
