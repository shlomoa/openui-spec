# Proposed Angular Material evidence register

Status: candidate entries only. The [canonical register](../../scopes/evidence.md) remains the authority for approved scope enrichment. This review register uses its four-column structure. “Authorizes” below always means **would authorize after explicit acceptance**; no row records an approval that has not occurred.

External framework examples establish observed patterns, not technology-neutral contracts. Proposal decision identifiers are review handles, not accepted decisions. The source baseline is Angular Material 22.1.7 at commit `e950f29dcfbda93c13bff0d1a632465364488249`. Citations are paraphrases; live documentation is not substituted for pinned evidence.

## Evidence exclusions

Test harnesses, schematics, build files, module registration, export barrels and package metadata remain traceability evidence in the survey. They do not authorize new UI scope objects. The absent legacy Sass targets remain an upstream packaging finding, not a taxonomy gap. No browser standard or accessibility certification is inferred from source code alone.

## Candidate field authorization and scope boundary

AM-P03–05 explicitly propose the exact keys, defaults and categories in their drafts as design decisions for review, rather than asserting that framework examples already authorize them. AM-E10 alone adds machine-bearing child applicability entries to an existing leaf; the other twelve amendments preserve parsed fields and child models. No new canonical folder is proposed, so there is no folder contract to approve beyond the Behaviors index update and existing folder-level clarifications.

Unresolved reference encoding, event shape, nested coordination and cleanup are listed in [BEHAVIOR_REVIEW.md](BEHAVIOR_REVIEW.md). Incorporate accepted evidence once per canonical leaf; do not append duplicate rows for an object already covered by another survey.
