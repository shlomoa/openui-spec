# Root Test Suite Plan

This document describes the repository's root Python test-suite strategy and the
tests implemented under `tests/` and `spec/tests/`: what each root test surface protects, how the
suite is organized, and how to run it locally.

Root Python tests protect the format SSOT in `spec/EBNF.txt`, the catalog-content
SSOT in `spec/scopes/`, their schema and catalog projections, examples, and
published documentation. They read the spec sources directly and fail when a
hand-authored source drifts from its own rules. Shared terminology is defined in
[`spec/scopes/scope.md` § Glossary](../spec/scopes/scope.md#glossary), so tests should
reference that vocabulary instead of duplicating definitions.
Exact concrete-document membership and instance flexibility are defined by the
[`Known object type`](../spec/scopes/scope.md#known-object-type) entry.

Repository validation commands and the CI gate overview live in
[`CONTRIBUTING.md` § Repository validation](../CONTRIBUTING.md#repository-validation).

Run from the repository root through the local virtual environment.

Windows (PowerShell):

```powershell
.\.venv\Scripts\python -m unittest discover -s tests -p "test_*.py"
```

Linux or macOS (Bash):

```bash
./.venv/bin/python -m unittest discover -s tests -p "test_*.py"
```

Each test file is a `unittest.TestCase` module discoverable by the standard
library `unittest` runner.

`spec/tests/` holds two more modules, run with
`python -m unittest discover -s spec/tests -p "test_*.py"`: `test_ebnf_parser.py`
(`OpenUiEbnfParserTest`) compiles `spec/EBNF.txt` with TatSu, and
`test_example_json_ebnf.py` (`OpenUiExampleJsonEbnfTest`) parses every worked
example with that grammar. The TypeScript tests of the npm package
(`tests/*.test.ts`) run with `npm test` from the repository root.

The worked example documents under `spec/examples/**` are covered for presence
and indexing by the README/spec contract tests (`examples/README.md` is part of
the expected spec set). The examples-format contract tests also load every
`*.example.json` document, validate it against `openui.schema.json`, and compare
every node's exact `type` literal with the generated catalog.

## Conventions

- **Sources of truth are authoritative.** `spec/EBNF.txt` owns the document
  format, and `spec/scopes/` owns catalog content. These tests protect their
  schema and catalog projections; downstream generator validation must not
  redefine either contract.
